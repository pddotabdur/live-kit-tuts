● Done. Now the answers to the other two questions.

  On "robotic feel" and SSML                                                                                                                            
  
  You're right that the agent feels robotic, but SSML won't fix that complaint. SSML controls how a single line is spoken (pauses, prosody, emphasis) — 
  it doesn't add variety. Your line للتأكد، آخر ٤ أرقام... will sound exactly the same the second time, just maybe with a <break time="200ms"/>
  somewhere. Also: Faseeh may not even support SSML; livekit.plugins.faseeh.TTS doesn't expose an SSML flag, so you'd have to verify with Munsit's API. 
  Probably wrong tool for this complaint.                   

  What actually fixes "robotic":                                                                                                                        
  
  1. Variant pools (cheap, instant). Replace each STATIC_LINE with random.choice(STATIC_LINES) — 2-3 paraphrases per slot. Zero LLM cost, zero new      
  latency, sounds different on retries. Best ROI.           
  2. LLM-generated transitions for non-critical lines. For things like the half-accept confirmation, the LLM could generate a Najdi reply naturally     
  given a hint ("acknowledge the half-payment commitment, mention the amount X SAR, thank them"). More natural, but: (a) you'd lose the _najdi_normalize
   digit-spelling guarantee since the LLM might output "1234" or "ألف ومئتين..." inconsistently, (b) adds an LLM TTFT to every spoken line (~+800ms),
  and (c) needs a system-level persona prompt to stay in character.                                                                                     
  3. Keep deterministic for legally-critical lines. Anything with debt amount, scheduled date, payment link — keep verbatim. Compliance reasons.
                                                                                                                                                        
  My honest recommendation: do (1) first. It's a 30-line change, instant payoff, no latency cost. Move to (2) only on lines where it matters            
  (half-accept, payment link wording, angry-handling) and where you're willing to eat ~800ms.                                                           
                                                                                                                                                        
  Why no system-level prompt?                                                                                                                           
  
  Two reasons it ended up this way:                                                                                                                     
                                                            
  1. The LLM here is a classifier, not a voice. Every spoken line is session.say(STATIC_TEXT). The model never speaks. So a "you are نورا, polite and   
  respectful debt collector" persona prompt has nothing to anchor — it can't shape audio that comes from precomputed strings.
  2. Per-stage tool-selection rules dominate. Each agent's prompt is tightly scoped to one decision. Adding shared persona text bloats every            
  classification call.                                                                                                                                  
   
  But — if you adopt option (2) above (LLM-generated transitions), a system-level persona prompt becomes essential. The pattern would be: a _PERSONA    
  constant prepended to every agent's instructions, defining voice/tone/identity in one place. It would also fix the "who are you" problem from earlier
  — the LLM could answer in character instead of looping the unclear handler.                                                                           
                                                            
  So the answer is: it's not there because it didn't need to be, but if you want naturalness it does need to be. The two questions are linked.

● All ten edits applied. Summary of what changes the customer experience:

  1. Empathy is now a first-class persona rule. PERSONA gained an "Empathy & negotiation style" block with concrete Arabic example pairs ("ما عندي فلوس"
   → "والله أتفهم وضعك..."). Every stage's LLM call sees this. Hardship is now framed as a signal to negotiate, not a refusal.
                                                                                                                                                        
  2. Date awareness is wired in. call_context_block now injects today's date, tomorrow, end-of-month, one-year-out + the Arabic weekday for             
  today/tomorrow. The LLM is told to translate any relative time ("next week", "بعد العصر") into a specific ISO date and confirm it back.
                                                                                                                                                        
  3. "Is this a good time?" check after name verification. Flow now goes: Stage1RightParty → AskGoodTimeAgent → IDVerify → Stage2. AskGoodTime tools:   
  good_time_now / bad_time_now / unclear. If bad time → ScheduleCallbackAgent which captures callback_time(day_iso, time_of_day) and ends with the new
  busy_callback closing hint that confirms the rescheduled time.                                                                                        
                                                            
  4. Installment math has hard server-side guardrails.                                                                                                  
  - Call data block declares "max 12 months, min ~833 SAR/month" right in the system prompt.
  - Stage3InstallmentAgent opener anchors with a concrete proposal (min_monthly SAR/month × 12) instead of asking open-endedly.                         
  - plan_agreed now takes monthly_amount, num_months, start_date_iso. If num_months > 12, the tool rejects and triggers a counter-offer LLM turn. If the
   total doesn't cover the debt (95% threshold for rounding), same. Only valid plans transition to recap.                                               
  - The customer-offers-100-SAR-per-week scenario now triggers a counter-offer.                                                                         
                                                                                                                                                        
  5. Stage 4 recap is now structured. The recap hint asks for total amount, instalment count + per-instalment value, first date, last date — all in     
  Arabic words. So the customer hears "we'll deduct 833 SAR per month for 12 months, starting Sunday May 4th, ending April 4th next year" instead of a  
  vague "we'll set up a plan for you".                                                                                                                  
                                                                                                                                                        
  6. Hangup-without-goodbye is fixed three ways. ClosingAgent.on_enter now: (a) session.interrupt() to stop any in-flight LLM/TTS, (b)                  
  session.input.set_audio_enabled(False) so the user's audio doesn't spawn a new turn while we close, (c) generate_reply(allow_interruptions=False) so
  the farewell can't be cut. The previous race (user asks "كم الفاتورة؟" → engine closes mid-LLM → no goodbye) should be eliminated.                    
                                                            
  7. Other touch-ups carried over from earlier: Stage3HalfPaymentAgent opener now leads with empathy. Stage 3 agents all have an unclear tool.          
  recap_corrected is split into recap_minor_correction vs wants_to_renegotiate (Stage 4 routes back to half-payment if the customer is materially
