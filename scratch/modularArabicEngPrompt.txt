● Created test_agent_en.py:1. Here's the design and what changed.

  Why your current agent drifts                                                 
   
  A single mega-prompt asks the LLM to remember which step it's on, decide if a 
  step was completed, and generate the next line — all simultaneously. The model
   has no enforced state, so it skips, repeats, or paraphrases. The fix LiveKit 
  recommends for scripted flows is multi-agent handoffs.                      

  The new structure                                                             
   
  Each script step is its own Agent subclass with a tiny, single-purpose prompt 
  that does one thing: classify the user's reply into a small set of tool calls.
                                                                                
  ┌──────┬─────────────────────┬─────────────────────────────────────────────┐  
  │ Step │        Agent        │          Branches (function_tools)          │
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤  
  │      │                     │ caller_available → IdentityAgent ·          │
  │ 1    │ GreetingAgent       │ caller_busy → hangup · unclear_response →   │
  │      │                     │ repeat                                      │  
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤
  │ 2    │ IdentityAgent       │ identity_confirmed → IDVerificationAgent ·  │  
  │      │                     │ wrong_person → hangup · unclear → repeat    │
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤  
  │ 3    │ IDVerificationAgent │ id_correct → DebtContextAgent ·             │  
  │      │                     │ id_incorrect → re-ask · unclear → repeat    │
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤  
  │      │                     │ will_pay_now → ClosingAgent · needs_time →  │
  │ 4    │ DebtContextAgent    │ ScheduleAgent · no_funds →                  │  
  │      │                     │ PartialPaymentAgent · denies_debt → hangup  │
  │      │                     │ · is_angry → empathize                      │  
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤
  │ 5a   │ ScheduleAgent       │ time_acceptable(date) · time_too_far ·      │
  │      │                     │ refuses_to_commit                           │  
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤
  │ 5b   │ PartialPaymentAgent │ accepts_partial(amount) · refuses_partial → │  
  │      │                     │  ScheduleAgent                              │  
  ├──────┼─────────────────────┼─────────────────────────────────────────────┤
  │ 6    │ ClosingAgent        │ speaks final line, hangs up                 │  
  └──────┴─────────────────────┴─────────────────────────────────────────────┘  
   
  Three things that make it deterministic                                       
                                                            
  1. session.say(text, allow_interruptions=False) — every scripted line         
  (greeting, closing, "wrong person, sorry") is spoken verbatim. The LLM never
  re-generates them, so no paraphrase drift.                                    
  2. function_tool returning the next Agent — handoffs are explicit. The LLM's
  only job is to classify the reply into one of N tool calls; the transition    
  itself is code, not prose.
  3. @dataclass CallData as AgentSession[CallData] userdata —                   
  identity_confirmed, id_verified, outcome, scheduled_date are typed state, not 
  free-text the LLM has to remember.
                                                                                
  Other notes                                               

  - chat_ctx=self.chat_ctx is passed on every handoff, so each new agent sees   
  the prior conversation.
  - temperature=0.3 (down from 0.7) — script consistency over creativity.       
  - STT switched to en-US, TTS to Cartesia sonic-2 with a default English female
   voice. Swap the voice UUID if you want a specific voice.                     
  - Same SIP/dispatch wiring as reem_agent.py — your existing dispatch.py will  
  work; just point AGENT_NAME=outbound-caller-en.                               
  - Run: uv run python test_agent_en.py dev (same as the others).

  translating the *_LINE constants and the per-agent instructions — the state   
  machine itself stays unchanged.
